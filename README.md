# architecture-warmhouse

# Задание 1. Анализ и планирование

### 1. Описание функциональности текущего состояния монолитного приложения

**Управление отоплением:**

- Пользователи могут управлять состоянием активности отопительной системы через веб-интерфейс
- Система поддерживает только включенное и отключенное состояние
- Система поддерживает один вид устройств - устройства для отопления

**Мониторинг температуры:**

- Система поддерживает мониторинг температуры в помещении
- Пользователи могут получать информацию о температуре через веб-интерфейс
- Система поддерживает регистрацию и обновление датчиков исключительно через сотрудников компании.

### 2. Анализ архитектуры монолитного приложения

- Язык программирования: Go
- База данных: PostgreSQL
- Архитектура: Монолитная
- Взаимодействие: Синхронное
- Масштабируемость: Ограничена
- Развертывание: Требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

- Обслуживание клиентов
  - подключение или отключение клиентов от системы
    - контекст: обслуживание клиента
    - контекст: регистрация или удаление устройств
  - Мониторинг работоспособности и устранение проблем с оборудованием
    - контекст: ответственность за работу умного отопления 
- Управление устройствами умного отопления
  - мониторинг температуры
    - контекст: сбор данных с датчиков температуры
  - изменение состояние системы
    - контекст: изменение состояния устройств

### **4. Проблемы монолитного решения**

- Риск ошибок. Изменение части приложения может непредсказуемо сказаться на работоспособности всего приложения.
- Даунтайм всего приложения при обновлении. При каждом обновлении системы требуется полная сборка и развертывание всей системы.
- Трудно управлять командой. Все модули системы тесно связаны между собой, трудно разделить задачи между участниками команды.
- Масштабируемость. Невозможно масштабировать отдельные части функционала системы.
- Технологические ограничения. Все компоненты привязаны к одному технологическому стеку
